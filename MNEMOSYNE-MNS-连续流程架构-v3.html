01 / CONTINUOUS ONLINE FLOW · 真实执行顺序

从 Hermes 回合进入，到上下文注入宿主模型；旁路在具体节点分叉并回流

主链只有一条

所有在线处理都沿着 ROUTE → RETRIEVE → HARD GATE → RANK → ASSEMBLE 前进。

存储是共享节点

检索、显式写入、session 回写都落到同一个 MemoryEntity Store，不是三套孤立数据。

旁路有明确落点

CONFLICT 影响注入；SESSION 写回存储；SHADOW 进入离线评估后显式回到 RANK。

严格区分在线与离线

虚线不是在线自学习。它表示显式操作、可选观测或人工/脚本触发的版本化部署。

02 / CONTINUOUS MODEL FLOW · RANK-HYBRID-01

同样采用流程图：两路输入在 Concatenate 汇合，之后只有一条评分路径

双输入同一编码器

Query 和 Memory 使用不同 prefix 进入同一个冻结的 multilingual E5。

两条特征支路

语义余弦与 12 个结构化特征在 Concatenate 汇合。

只有一条评分路径

13 维输入 → StandardScaler → Logistic Ranker → Top-K，没有旁路跳过融合。

策略不在模型里

scope、egress、validity、authority 和 token budget 由系统规则控制。
